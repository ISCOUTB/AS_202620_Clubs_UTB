# ADR 000X: Integración síncrona (REST) y asíncrona (eventos)

## Estado
Aceptado
## Fecha
20/09/2026

## Contexto
Crear una publicación exige confirmación inmediata al club. Avisar a
miembros e interesados no debería hacer esperar a nadie ni fallar la
creación si el notificador está caído (escenario U2).

## Decisión
- Comandos y consultas: REST síncrono, contrato en docs/api/openapi.yaml
- Notificaciones: evento de dominio `publicacion.creada`, contrato en
  docs/api/asyncapi.yaml, emitido después de confirmar la creación
- Ambos contratos con SemVer propio y verificados en el pipeline

## Alternativas descartadas
- Todo síncrono: la creación se bloquea si falla la notificación
- Todo asíncrono: el cliente no recibe confirmación inmediata
- Polling desde la app: consumo innecesario y notificaciones tardías

## Consecuencias
- (+) Un fallo del notificador no afecta la publicación
- (+) Se pueden agregar consumidores sin tocar el emisor
- (-) Consistencia eventual: la notificación llega después
- (-) Falta decidir el mecanismo de transporte (broker, cola, etc.)
- (-) Hay dos contratos que mantener y versionar

## Verificación
Workflow contrato.yml: lint, pruebas de contrato y detección de cambios
incompatibles.
